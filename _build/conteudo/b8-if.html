01
O que você vai aprender

Por que isso importa

Em uma frase

Com IF, o fluxo se adapta: lead qualificado vai por um caminho, lead frio por outro.

IF é o nó mais usado pra controle de fluxo. Sem ele, todo workflow trata todo input igual: manda o mesmo e-mail pra todo lead, registra todo erro do mesmo jeito.

A pegadinha que vai te custar tempo: comparar uma string "42" com o número 42 retorna false. Sintoma: a condição parece certa mas o fluxo vai pro ramo errado. Quando isso acontece, sempre suspeite primeiro do tipo de dado.

02
O conceito, e é um só

Conceito central

O conceito desta aula

O IF tem 1 entrada e 2 saídas: True e False

Cada item da entrada é avaliado individualmente: se atender a condição, sai pelo True; se não, pelo False.

Analogia

O IF é o porteiro de 2 portas: entrou no critério → porta verde; não entrou → porta vermelha. É a sticky do nó no exemplo-nodes-v2.

  • O pacote que chega = cada item
  • A pergunta do porteiro = a condição
  • Porta verde / porta vermelha = saída True / saída False

O porteiro, em slide. A armadilha do rodapé é a seção 03 inteira, e o teste de 16/09 mostrou que hoje ela nem chega a ser silenciosa.

Como funciona na prática

Por que tipo de dado quebra o IF

Os 5 tipos do n8n estão detalhados na aula 1. O ponto crítico pro IF: comparar tipos diferentes não dá erro vermelho: entrega resultado errado em silêncio. A tabela abaixo é o que mais aparece no dia a dia.

Conferido em 16/09/2026: na versão atual, o IF grita

Na conta de teste, o IF (versão 2.3) vem com a validação de tipo estrita ligada: comparar "32" (string) com um operador de número parou a execução com o erro vermelho Wrong type: '32' is a string but was expecting a number (execução 420, na aula 1). O silêncio que esta aula descreve acontece quando a opção "Convert types where required" está ligada, ou em versões anteriores. Nos dois casos a correção é a mesma da tabela: converter o tipo antes de comparar.

Regra de ouro

Quando o IF parece certo mas vai pro ramo errado, abra o JSON view do nó anterior e veja se o valor está entre aspas (string) ou sem aspas (number/boolean).

Configurando o IF

  1. Adicione o nó IF depois do nó que produz o dado a avaliar.
  2. Renomeie descrevendo a decisão: ❓ Score qualifica?, não IF.
  3. Em Conditions, adicione a condição: Campo (em Expression) {{ $json.score }}; Operação larger than; Valor 70.
  4. Conecte os ramos True e False a nós diferentes.

05
A cerca

Pegadinhas

Comparar string com number sem converter

Resultado errado silencioso. Sempre use Number($json.campo) ou String($json.campo) quando os tipos podem divergir.

Esquecer do caso "valor vazio"

Se o campo pode vir null ou "", adicione uma condição extra: is not empty. Senão item vazio vai parar no ramo False sem você ter previsto.

Renomear como "IF"

Daqui a 2 semanas, com 3 IFs no canvas, você não sabe qual é qual. Sempre nome descritivo da decisão.

Misturar AND e OR sem agrupar

IF tem combinação de condições. Cuidado com prioridade lógica; teste cada caminho.

Não testar o ramo False

Fácil testar só com input que vai pro True. Sempre envie um input que dispare o False também.
