02
O conceito, e é um só

Conceito central

O conceito desta aula

JSON é um jeito de organizar dados em texto: cada dado tem um nome (chave) e um valor

JSON (JavaScript Object Notation) é como o n8n, e quase toda API moderna, passa informação de um lado pro outro.

Analogia

Pensa em JSON como um sistema de etiquetas: cada dado tem um nome (chave) e um valor.

  • A etiqueta = o par chave:valor
  • O nome na etiqueta = a chave ("nome")
  • O que está escrito = o valor ("Maria")
Um JSON com os 5 tipos 
{
  "nome": "Maria",
  "idade": 32,
  "ativa": true,
  "interesses": ["IA", "n8n", "automação"],
  "endereco": {
    "cidade": "Fortaleza",
    "estado": "CE"
  }
}

Cada linha é um par chave:valor: o nome do dado de um lado, o valor do outro.

A etiqueta, em slide. Os dados da etiqueta são os do instrutor, que fez o exemplo em sala; no seu JSON, o valor é o seu.

Os 5 tipos de dados

Olhe o exemplo acima. Já tem os 5 tipos que você precisa conhecer:

TipoComo reconhecerExemplo

A regra-mãe: string vs number

string e number são confundidos o tempo todo

"32" (string com aspas) não é o mesmo que 32 (número). O n8n trata diferente.

  • "32" + 1 → "321" (concatena texto)
  • 32 + 1 → 33 (soma)
  • "10" == 10 → false (tipos diferentes)
  • "10" > 5 → comportamento imprevisível

A regra-mãe, em slide. As duas primeiras linhas da lista acima são as duas colunas: "321" de um lado, 33 do outro.

Armadilhas frequentes que quebram seus fluxos

SituaçãoProblemaSintoma

Quando uma condição parece certa mas o fluxo vai pro ramo errado, suspeite primeiro do tipo de dado

Abra o JSON view e veja se o valor está entre aspas (string) ou sem aspas (number/boolean).

03
Como funciona

Como funciona na prática

Onde olhar o JSON

Cada nó executado oferece 3 modos de visualização do output (Table, JSON, Schema). O detalhamento está na aula 2: por enquanto basta saber que a aba JSON é a fonte de verdade, e é nela que se confere se um valor é string (com aspas) ou number (sem).

JSON aninhado: objeto dentro de objeto

Quando o valor é outro JSON, você navega de fora pra dentro. No exemplo da Maria, pra ler a cidade você usa {{ $json.endereco.cidade }}. Vai navegando como pasta dentro de pasta.

Convertendo tipos quando precisar

Quando você não consegue evitar o tipo errado na origem, converte no Set node ou na Expression:

ConversãoExpression
Number → String{{ String($json.idade) }}
Texto pra minúsculas{{ $json.email.toLowerCase() }}

05
A cerca

Pegadinhas

Tudo no n8n é array

Mesmo que você veja "1 item", aquele item está dentro de um array. Detalhamento na aula 2.

Aspas matam

"32" ≠ 32. Sempre confira o tipo no JSON view antes de criar IF/Switch.

Object aninhado vira fonte de confusão

{{ $json.pessoa.endereco.cidade }}: e se endereco for null? Quebra.

Set node respeita o Type que você escolhe

Se você define um campo como String e bota 32, vai sair "32". Cuidado.

API que retorna null em campo numérico

A Expression retorna null. Comparações com null geralmente retornam false. Trate antes do IF.
