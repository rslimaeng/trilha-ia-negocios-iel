Por que isso importa

Em uma frase

Quem lê JSON resolve; quem fica só na Table fica perdido.

Você vai bater de frente com perguntas como: "por que meu nó rodou 3 vezes em vez de 1?", "por que o e-mail saiu vazio?", "por que {{ $json.nome }} retorna [object Object]?". 9 em cada 10 dessas dúvidas têm a mesma raiz: não entender que o n8n trabalha com array de objetos e que a Table do output esconde isso.

02
O conceito, e é um só

Conceito central

O conceito desta aula

Todo dado que sai de um nó é um array de objetos. Mesmo quando tem 1 item só.

Array vs objeto: o casamento que move tudo

ArrayObjeto
Sintaxe[ ]{ }
AcessoPor posição: array[0]Por chave: objeto.nome

A regra-mãe do n8n, a frase acima, significa que cada nó produz uma estrutura tipo:

Um array de três objetos 
[
  { "nome": "Ana",   "cargo": "Gerente"  },
  { "nome": "Bruno", "cargo": "Analista" },
  { "nome": "Carla", "cargo": "Diretora" }
]

O array é a lista. Cada objeto dentro é um item. O nó seguinte processa um item por vez, em ordem: igual você pega maçãs antes de bananas no mercado.

Por que isso importa na prática

  • Sua planilha do Google Sheets tem 50 linhas → o nó de Sheets entrega 50 itens.
  • O próximo nó executa 50 vezes: uma pra cada linha. Automaticamente.
  • Você configura a lógica uma vez; ela roda N vezes sozinha.
Analogia da lista de compras

O n8n trata um array como sua lista do mercado. Vai passando item por item, na ordem em que estão. Você configura uma vez "o que fazer com cada item"; ele faz pra todos.

  • A lista do mercado = o array
  • Cada item da lista = um objeto
  • "O que fazer com cada item" = o nó, configurado uma vez

A lista de compras virou esteira em sala. As 50 linhas da planilha são os 50 pacotes; a frase de baixo é a primeira pegadinha da cerca.

Quando isso vira pegadinha

SituaçãoO que está acontecendo
Esperava 1 execução, rodou 3Entrou um array de 3 itens: comportamento esperado, não bug
Tentou acessar {{ $json.nome }} num nó que recebeu array de 3Cada item é processado separadamente; $json.nome é o nome do item atual

03
Como funciona

Os 3 modos de visualização do output

Quando você clica num nó executado, vê 3 abas no painel da direita. Cada uma serve pra coisa diferente.

AbaO que mostraQuando usar
JSONO dado cru, do jeito que táEsta é a verdade. Sempre que algo dá errado, é aqui que aparece.
TableVisão de planilha: colunas e linhasVer vários itens rápido, conferir contagem
SchemaA estrutura sem os valoresMapear "o que existe" sem distração

O que cada uma esconde

  • Table esconde objetos aninhados. Se você tem { "endereco": { "cidade": "Fortaleza" } }, a Table mostra [object Object] na coluna endereco. Não dá pra confiar pra debugar.
  • JSON mostra tudo, inclusive aninhamentos. É a fonte de verdade.
  • Schema ignora valores e mostra só os nomes das chaves e tipos. Útil pra entender estrutura de uma API nova.
Hábito profissional

Quando o nó parece que não fez o esperado, abra primeiro o JSON view. A Table mente por simplificação; o JSON conta a verdade.

Table contra JSON, em slide. O 32 entre aspas do lado do raio-X é o experimento da aula 1 de novo.

Visualizando o array de itens

No JSON view, os itens aparecem numerados:

Os três itens, numerados 
Item 0: { "nome": "Ana",    "cargo": "Gerente"  }
Item 1: { "nome": "Bruno",  "cargo": "Analista" }
Item 2: { "nome": "Carla",  "cargo": "Diretora" }

O nó seguinte vai processar Ana, depois Bruno, depois Carla: automaticamente.

Acessando campos com Expression

  • {{ $json.nome }} → pega o campo nome do item atual (varia a cada execução do array).
  • {{ $json.endereco.cidade }} → navega objeto aninhado.
  • {{ $json.tags[0] }} → primeiro item de um array dentro do objeto.

05
A cerca

Pegadinhas

"Por que rodou 3 vezes?"

Porque entrou um array de 3 itens. Não é bug. É comportamento padrão.

$json ≠ $json.campo

O primeiro é o objeto inteiro do item atual; o segundo é um campo específico. Jogar $json num campo que espera texto produz [object Object].

Object aninhado quebra a Table

Vá pro JSON view.

Confundir array com objeto

[ ] é lista; { } é par chave:valor. Misturar quebra Expressions.

Esquecer que cada item processa separadamente

Se você usa expressões esperando agregação, vai pegar só o último ou o primeiro item, não a soma.
