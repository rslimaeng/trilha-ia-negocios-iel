O que você vai aprender

Por que isso importa

Em uma frase

Esquecer o Fallback é a fonte mais comum de "perdi um dado e não sei onde foi parar".

Quando você precisa rotear o fluxo por 3 ou mais valores possíveis (departamento, categoria, nível, idioma), aninhar IFs vira um nó indistinguível do anterior depois de 2 caminhos. Switch resolve isso com uma saída por valor, e, crítico, uma saída Fallback pra valores que não casam com nenhum caso.

02
O conceito, e é um só

Conceito central

O conceito desta aula

O Switch tem 1 entrada e múltiplas saídas. Cada saída tem uma regra.

O item vai pela saída cuja regra ele atender.

Analogia

O Switch é a central de várias rotas: 1 entrada → várias saídas, escolhe pela regra. É a sticky do nó no exemplo-nodes-v2; em sala virou a central de triagem, com o Fallback como o cesto do "não sei".

  • A etiqueta do pacote = o valor do campo (categoria, departamento)
  • Cada trilho = um output com regra
  • O cesto do não sei = a saída Fallback

A central de triagem, em slide. O trilho laranja é o que esta aula insiste: sem o cesto, o pacote não identificado some.

IF vs Switch: quando usar cada um

SituaçãoUse
3+ caminhos por valor de campo (vendas / marketing / suporte)Switch
Lógica composta (AND/OR de várias condições por ramo)IFs encadeados ou Switch em modo Expression
Regra prática

3 ou mais ramos = Switch. Aninhar 3 IFs vira código ilegível.

03
Como funciona

Como funciona na prática

Modos do Switch

  • Rules mode: você define cada regra explicitamente (igual ao IF, mas com várias). Use quando os critérios são variados.
  • Expression mode: uma única Expression que retorna o nome do output (return $json.departamento). Use quando o roteamento é direto pelo valor de um campo.

Configurando Switch (Rules mode)

  1. Adicione o Switch depois do nó que produz o dado de roteamento.
  2. Renomeie descrevendo o roteamento: 🔀 Roteia por departamento.
  3. Em Mode, selecione Rules.
  4. Pra cada caminho, adicione uma rota: Output Name (ex.: vendas); Conditions (ex.: {{ $json.departamento }} equals Vendas).
  5. Sempre ative a saída Fallback: pra casos que não casam com nenhuma regra.
  6. Conecte cada output a um nó diferente.

Por que Fallback registra erro?

Porque se chegou um valor que você não previu (ex.: "NaoSei"), você quer saber. Sem Fallback, o item somem do fluxo silenciosamente.

Redesenho do canvas, a partir da execução de teste (execução 439, 16/09/2026). Pra rodar sem Form, Slack, Email nem Sheets, os 5 tickets entraram por um Set e os destinos são Sets com o nome do destino. O ticket 5, categoria "NaoSei", saiu pela porta Fallback: é o cesto funcionando.

A cerca

Pegadinhas

Esquecer da saída Fallback

Item com valor inesperado some sem aviso. Sempre ative o Fallback e conecte a um nó que registre/notifique. Item ignorado é dado perdido.

Switch com regras sobrepostas

Se duas regras casam ao mesmo tempo, o n8n entrega ao primeiro match. Cuidado com regras tipo "contém X" + "contém Y" quando o valor pode ter ambos.

Tipo de dado errado nas regras

Mesmo problema do IF. "42" (string) ≠ 42 (number). Confira no JSON view antes de configurar.

Output sem nome

Fica Output 1, Output 2. Pior pra debugar. Sempre nomeie cada output com a regra que ele representa.
