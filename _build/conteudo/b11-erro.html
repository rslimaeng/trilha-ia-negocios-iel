01
O que você vai aprender

Por que isso importa

Em uma frase

Automação que falha em silêncio é pior que automação que não existe.

Repare no porquê, que não é óbvio. Quando você não automatiza, você sabe que precisa fazer na mão, e faz. Quando automatiza e o fluxo quebra sem avisar, você acha que está funcionando, e continua achando por semanas. O problema aparece pela pior porta possível: o cliente reclamando.

É por isso que o aviso não é um extra de quem é organizado. Error Trigger é o cinto de segurança de qualquer fluxo que vai para produção, e o custo dele são cinco minutos, uma vez.

02
O conceito, e é um só

O fluxo que vigia os outros

O conceito desta aula

Error Trigger é um gatilho especial: ele não escuta o mundo lá fora, escuta os seus próprios fluxos quebrando

Ele pega

Erro dentro de uma execução real

O fluxo disparou sozinho, rodou, e um nó falhou no meio do caminho. Aqui ele avisa.

Ele pega

Qualquer nó do fluxo vigiado

Não importa se quebrou no primeiro ou no último: ele recebe o nome do nó que falhou.

Ele não pega

Fluxo que nem chegou a disparar

Schedule desativado, webhook com URL errada. Ele detecta erro dentro da execução, não a ausência de execução.

Ele não pega

Teste seu, no botão Execute

Quando você clica para testar, ele não dispara. Só em execução real, automática.

É como o alarme de temperatura do freezer

O freezer da cozinha não avisa quando está funcionando: ele avisa quando parou. E o aviso não vem do freezer, vem de um sensor separado, que existe só para isso e que você ligou uma vez. Sem o sensor, você descobre o problema abrindo a porta e sentindo o cheiro, que é sempre tarde demais.

  • O freezer é o fluxo que faz o trabalho de verdade
  • O sensor é o fluxo de Error Trigger, separado e ligado o tempo todo
  • O fio entre os dois é o vínculo nas Settings, que é a parte que todo mundo esquece
  • O cheiro ao abrir a porta é o cliente ligando

O que ele entrega quando dispara

CampoO que vem dentro
workflow.nameO nome do fluxo que falhou
execution.lastNodeExecutedO nome do nó que falhou
execution.error.messageA mensagem de erro, a mesma que aparece no nó vermelho

O execution.url é o campo mais valioso dos cinco. Com ele no e-mail, você sai da caixa de entrada e cai direto no canvas pintado, no nó vermelho, pronto para o método de 4 passos da aula 1.

Como funciona

Duas partes, e a segunda é a que some

ACriar o fluxo que avisa, e ativar
→
BApontar cada fluxo principal para ele

Criar o avisador não basta. Ele fica ali, ativo e mudo, até alguém dizer a cada fluxo principal que é para ele que se avisa. Essa ligação é feita uma vez por fluxo, nas Settings.

A
Criar o fluxo que avisa
  1. Fluxo novo. Renomeie para 🚨 Error Handler.
  2. Adicione o gatilho Error Trigger. É um gatilho único no n8n: procure por "Error".
  3. Adicione um Gmail (Send) com o assunto e o corpo abaixo.
  4. Salve e ative. Sem o Active ligado, ele não escuta nada.
Assunto do e-mail 
🚨 Erro em: {{ $json.workflow.name }}
Corpo do e-mail 
Workflow {{ $json.workflow.name }} falhou no nó
{{ $json.execution.lastNodeExecuted }}.

Erro: {{ $json.execution.error.message }}

Ver execução: {{ $json.execution.url }}
Se travar no texto do e-mail

Comece pelo que você vai querer saber às 7h da manhã, de celular, sem abrir o computador: qual fluxo quebrou, e é urgente ou pode esperar. O resto é detalhe que o link resolve.

Não vale: mandar o erro técnico puro no assunto. Daqui a dois meses você vai ter três desses na caixa e nenhum diz de qual fluxo é.
Deu certo quando

O fluxo tem dois nós, está salvo, e o botão Active no canto superior direito está ligado.

B
Ligar o fluxo principal ao avisador
  1. Abra o fluxo que você quer monitorar.
  2. Menu …, no canto superior direito, e depois Settings.
  3. No campo Error Workflow, escolha o 🚨 Error Handler.
  4. Salve.
Deu certo quando

Você reabre as Settings do fluxo principal e o campo Error Workflow mostra o nome do avisador. Esse passo se repete em cada fluxo que for para produção, um por um.

05
A cerca

Pegadinhas

Ele só dispara se o fluxo principal chegou a rodar

Se o fluxo nem disparou, porque o Schedule está desativado ou a URL do webhook está errada, o Error Trigger não percebe nada. Ele detecta erro dentro da execução, não a falta dela.

O avisador precisa estar ativado

Sem o botão Active ligado no próprio Error Handler, ele não escuta. Criar e salvar não liga.

Não esqueça de vincular nas Settings

Criar o avisador não basta: cada fluxo principal precisa ser configurado apontando para ele, um por um.

Não use o mesmo avisador para fluxos muito diferentes

Se um é crítico, como cobrança, e outro é secundário, como relatório, separe os avisadores. Você pode querer reagir diferente: Telegram na hora para um, e-mail diário para o outro.

Ele não captura o seu teste manual

Quando você clica em "Execute Workflow" para testar, ele não dispara. Só em execução real, por Schedule, webhook ou evento de aplicativo.
