Por que isso importa

Em uma frase

System Prompt mal escrito = agente alucina, inventa formato, escolhe tool errada. Bem escrito = agente confiável que faz o que precisa fazer e nada mais.

A diferença entre os dois não é talento, é metodologia. Tentar escrever o System Prompt "perfeito" antes de qualquer teste quase sempre falha. A abordagem que funciona é começar vazio e adicionar 1 linha por vez baseado no que o teste mostrou.

02
O conceito, e é um só

Conceito central

O conceito desta aula

Os 3 papéis dentro do prompt: System / User / Assistant

Toda conversa com um modelo de linguagem é organizada em mensagens com papéis:

  • System: quem o agente é, como deve se comportar. Permanente.
  • User: o pedido que chega na execução. Muda toda hora.
  • Assistant: exemplo de resposta esperada. Raramente usado, só pra calibrar formato.

Reactive Prompting: a metodologia

Analogia: o manual do funcionário

Você não escreve o manual completo do funcionário antes de vê-lo trabalhar. Observa, vê o que ele faz errado, corrige uma instrução por vez. System Prompt funciona igual.

  • O manual completo = as 50 linhas de System Prompt escritas antes de qualquer teste
  • Vê-lo trabalhar = testar com o System Prompt vazio
  • Corrigir uma instrução por vez = adicionar 1 linha e testar de novo com o mesmo input

O ciclo:

  1. System Prompt vazio → testa, vê o comportamento padrão.
  2. Adiciona 1 ferramenta → testa de novo.
  3. Observa o output → o que estava errado?
  4. Adiciona 1 linha no System Prompt que corrija.
  5. Testa de novo com o mesmo input.
  6. Volta ao 3 até estar consistente.
Nunca mude duas coisas ao mesmo tempo

Se mudar System Prompt e ferramenta e modelo, e parar de funcionar, você não sabe o que quebrou.

Template estruturado: 6 partes

Quando o System Prompt cresce além de 5-6 linhas, organize em 6 partes. Esse é o template que sustenta agente em produção:

O template de 6 partes 
ROLE     — quem você é
GOAL     — o que você precisa entregar
TOOLS    — o que você pode usar (e quando)
RULES    — o que sempre/nunca fazer
NOTES    — informação contextual extra (data atual, fuso, etc.)
OUTPUT   — formato da resposta esperada
03
Como funciona

Como funciona na prática: exemplo aplicado

Agente que marca reuniões no Google Calendar:

System Prompt do agente de reuniões 
ROLE
Você é um assistente pessoal especializado em agendar reuniões no Google Calendar.

GOAL
Receber pedidos de agendamento em linguagem natural e criar eventos no Calendar.

TOOLS
- get_contact: busca contato pelo nome no Google Contacts.
- check_availability: verifica disponibilidade no Calendar entre 2 horários.
- create_event: cria evento no Calendar.

RULES
1. SEMPRE busque o contato (get_contact) antes de criar evento.
2. SEMPRE verifique disponibilidade antes de criar.
3. Se houver conflito de horário, NUNCA crie. Avise o usuário.
4. Confirme com o usuário antes de criar evento.

NOTES
- A data de hoje é {{ $now.toFormat('yyyy-MM-dd') }}.
- O fuso horário do usuário é America/Fortaleza.
- Padrão de duração de reunião é 30 minutos quando não especificado.

OUTPUT
Resposta curta em texto natural. Confirmações em formato:
"Reunião com [nome] marcada para [data] às [hora]."

Por que cada parte importa

  • ROLE sem foco = agente genérico inútil. Foque numa especialidade.
  • GOAL ausente = agente não sabe quando terminou. Defina o que é "tarefa cumprida".
  • TOOLS não mencionadas no prompt = agente esquece que existem. Sempre liste.
  • RULES = onde você previne os erros que viu nos testes.
  • NOTES = a IA não sabe que dia é hoje, nem qual é seu fuso. Diga.
  • OUTPUT = sem isso, o agente inventa formato.

A demonstração

Exemplo guiado: escrevendo do zero com Reactive Prompting

Exemplo guiado · um agente qualificador de leads, uma linha por vez

Você vai construir um agente qualificador de leads. Em vez de escrever 50 linhas de System Prompt logo de cara:

Passo 1, vazio: envie um lead de teste com System Prompt em branco. Veja o que sai.

Passo 2, adicione formato:

Passo 2 
Retorne APENAS um JSON válido com os campos: nome, score, recomendacao.

Teste. Provavelmente o JSON vem dentro de markdown.

Passo 3, corrija:

Passo 3 
Retorne APENAS um JSON válido. Não inclua blocos markdown. Apenas o JSON puro.

Passo 4, corrija a alucinação:

Passo 4 
Se uma informação não estiver presente no input, score = 0 e
justificativa = "Informação não fornecida". Nunca invente.

Continue até o agente responder consistente em 5 testes seguidos.

Não rodado em 09/2026: os quatro passos são o caminho do material, sem execução numa conta de teste. O "provavelmente o JSON vem dentro de markdown" é o que o autor observou em abril de 2026.

05
A cerca

Pegadinhas

System Prompt vago ("seja útil")

Agente genérico, decide errado em casos de borda.

Esquecer da data atual

Sempre inclua {{ $now.toFormat('yyyy-MM-dd') }} em NOTES.

Não dar exemplo de output

O agente inventa formato.

Regras conflitantes

"sempre confirme" + "responda rápido sem perguntar" → agente vira indeciso.

Tudo no User message

Instrução permanente vai no System.

Não atualizar System Prompt depois de erro real

Reactive Prompting nunca termina.
