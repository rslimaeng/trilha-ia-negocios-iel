01
O que você vai aprender

Por que isso vale a pena

Em uma frase

Marcar reunião por DM/WhatsApp consome 15-20 min/dia entre confirmar disponibilidade, escrever convite e responder reagendamento.

Esse agente faz tudo isso em 5 segundos via chat: escala pra time inteiro com a mesma config. Aplicação típica: assistente de gestor, recepção de consultoria, atendimento de clínica/escritório.

"15-20 min/dia" é estimativa do autor, de abril de 2026.

Pré-requisitos
  • Fluxo prático 1 funcionando.
  • Credencial Google (OAuth2) com escopo de Calendar.

Conferido em 21/09/2026 na definição do nó Google Calendar Tool (1.3): a credencial que ele pede é a Google Calendar OAuth2 API, uma por serviço, como a aula 4 do B9 mostrou pra Gmail, Sheets e Drive. O que se reaproveita é o projeto e o cliente OAuth do lado do Google.

Passo a passo

1

2
Adicionar 2 tools

Tool 1, check_availability (Google Calendar → Get Events):

Tool Description do check_availability 
Verifica se há eventos no Google Calendar entre dois horários.
Use SEMPRE antes de criar um evento, pra confirmar que o
horário está livre.
Parâmetros: start (ISO 8601), end (ISO 8601).
  • Parâmetros: Time Min = {{ $fromAI('start') }}, Time Max = {{ $fromAI('end') }}.

Tool 2, create_event (Google Calendar → Create Event):

Tool Description do create_event 
Cria um evento no Google Calendar.
Use depois de check_availability confirmar que o horário está livre.
Parâmetros: title, start (ISO 8601), end (ISO 8601), description (opcional).
  • Parâmetros: mapeados com $fromAI('campo') cada um.

Conferido em 21/09/2026 na definição do nó Google Calendar Tool (1.3): em Event → Get Many os campos são Time Min e Time Max; em Event → Create são Start, End, e o título fica em Additional Fields → Summary, a descrição em Description. Existe também a operação Calendar → Availability, que responde se um horário está livre.

O que esperar

Duas tools penduradas na porta Tools do agente, cada uma com nome curto e a descrição acima no campo Tool Description.

3
Atualizar o System Prompt
System Prompt do Agente Calendar 
ROLE
Você é um assistente que marca compromissos no Google Calendar de (seu nome).

GOAL
Receber pedidos de agendamento em linguagem natural e criar eventos.

TOOLS
- check_availability: verifica disponibilidade entre 2 horários.
- create_event: cria evento no Calendar.

RULES
1. SEMPRE chame check_availability ANTES de create_event.
2. Se o horário NÃO estiver livre, NUNCA crie. Avise e sugira outro.
3. Confirme com o usuário ANTES de criar (mostre proposta primeiro).
4. Padrão de duração é 30 minutos se o usuário não especificar.

NOTES
- Hoje é {{ $now.toFormat('yyyy-MM-dd') }}.
- Fuso: America/Fortaleza.
- Quando o usuário disser "amanhã", "semana que vem" etc., calcule a partir de hoje.

OUTPUT
Confirmações curtas, em texto:
"Reunião '[título]' marcada para [data] às [hora]."
Se conflito:
"Conflito com [evento existente]. Sugestão: [outro horário]."

No material, o ROLE diz "no Google Calendar do Rafael"; aqui o calendário é o seu. O resto do prompt é como está.

4
Testar

Mandar no chat: "Marca uma reunião com cliente X amanhã 15h por 1h."

Sequência esperada
  1. Agente chama check_availability (15h-16h).
  2. Recebe lista de eventos. Se vazia, prossegue.
  3. Apresenta proposta no chat.
  4. Você confirma "sim".
  5. Agente chama create_event.
  6. Confirma criação.
Se o agente criou o evento sem checar a agenda

Agente esquece de chamar check_availability: ajustar RULE 1.

Não vale: trocar o modelo. Iterar é parte do processo: ajuste uma regra e teste de novo com o mesmo pedido.

O que esperar

Primeira vez vai dar errado. Erros típicos:

  • Agente esquece de chamar check_availability → ajustar RULE 1.
  • Datas em formato errado → revisar descrição da tool.
  • Agente não pergunta confirmação → ajustar RULE 3.
Iterar é parte do processo

É raro um agente funcionar redondo na primeira tentativa. Reactive Prompting em ação.
