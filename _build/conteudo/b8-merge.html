01
O que você vai aprender

Por que isso importa

Em uma frase

O Merge é o nó que reúne os caminhos, e ele tem dois modos com objetivos opostos. Confundir os dois é a causa de execução com output vazio que parece sem motivo.

À medida que seus workflows crescem, bifurcações aparecem naturalmente. Um IF cria 2 caminhos. Você dispara 2 buscas em paralelo pra ganhar tempo. Em todos esses casos, vai precisar reunir os caminhos antes de continuar pro próximo passo.

02
O conceito, e é um só

Conceito central

O conceito desta aula

O Merge tem 2 entradas e 1 saída. A pergunta que decide o modo é uma só: em uma execução, quantos caminhos vão ter dados?

Ele recebe dados de duas origens diferentes e os entrega num único fluxo seguinte.

  • Apenas um caminho → modo Choose Branch.
  • Os dois caminhos → modo Combine by Position (ou Combine by Key).
Conferido em 16/09/2026: depois de um IF, quem passa o item é o Append

Antes de escrever esta aula, o caso "apenas um caminho" foi montado numa conta de teste: um IF de 2 ramos, cada ramo num Set, os dois no Merge, e um nó depois. Os três modos foram rodados com o mesmo item.

  • Append (execução 441): o Merge passou o item do ramo que chegou, 1 item, e o nó seguinte rodou. ✅
  • Choose Branch (execução 442): o Merge nunca rodou. Ficou esperando a entrada 2, que o IF não alimentou, e o nó seguinte não executou. Sem erro vermelho.
  • Combine by Position (execução 443): o Merge rodou e saiu vazio, com a dica "Consider enabling Include Any Unpaired Items". O nó seguinte não executou.

Na versão atual do n8n, o Choose Branch é descrito como "espera todas as entradas" e serve pra escolher os dados de uma entrada quando todas chegaram: não pra reunir os ramos de um IF. Onde esta aula diz Choose Branch para o caso do IF, faça Append. O curso oficial do n8n e sete relatos do acervo dizem o mesmo. As frases do Notion ficaram como estão; o teste está na seção 04.

Modo 1: Choose Branch (caminhos alternativos)

Use quando os dois caminhos vêm de um IF (ou Switch) e só um deles vai receber o item naquela execução. O Merge espera o que chegar e passa adiante.

Analogia

Dois funcionários em turnos alternados: um de manhã, outro à tarde. Em qualquer momento, só um está trabalhando. O Merge sabe que só vai chegar um e espera por ele.

  • Os dois turnos = os dois ramos do IF
  • Só um trabalhando = só um ramo tem item por execução
  • Esperar por ele = o Merge (no teste, o Append) passa o que chegou

Modo 2: Combine by Position (processamento paralelo)

Use quando você divide o fluxo em dois caminhos que rodam ao mesmo tempo e você precisa somar os campos dos dois resultados num item só.

Analogia

Dois funcionários processando o mesmo pedido em paralelo: um cuida da parte financeira, outro da parte logística. No final, você junta os dois pra ter o pedido completo.

  • Os dois funcionários = os dois caminhos paralelos
  • O mesmo pedido = o mesmo item, com campos diferentes em cada um
  • Juntar os dois = Combine by Position
Existe também Combine by Key

Pareia itens pelo valor de um campo (ex.: cliente_id). Lógica igual à do Combine by Position, mas em vez de parear pela posição, pareia pelo valor da chave. Use quando os dois caminhos podem trazer itens em ordens diferentes.

O slide desta aula (o cruzamento, m3-11) diz "Choose Branch deixa o pacote passar" para o caso do IF; como o teste não confirmou, ele ficou de fora, por decisão do prompt de 14/09.

03
Como funciona

Como funciona na prática

Configurando Choose Branch
  1. Adicione um nó Merge depois dos dois ramos do IF.
  2. Conecte o ramo True na entrada 1.
  3. Conecte o ramo False na entrada 2.
  4. No nó Merge, em Mode, selecione Choose Branch.
  5. Configure qual entrada tem prioridade (geralmente Input 1).

No teste de 16/09, o passo 4 com Append foi o que fez o item passar; com Choose Branch o Merge não rodou.

Configurando Combine by Position
  1. Os dois caminhos paralelos chegam ao nó Merge.
  2. Conecte cada um numa entrada (qualquer ordem).
  3. Em Mode, selecione Combine by Position.
  4. Garanta que os dois caminhos produzem a mesma quantidade de itens: se um tem 3 e o outro 2, o Merge descarta o item sem par.

05
A cerca

Pegadinhas

Usar Combine by Position depois de um IF

Resultado: array vazio, sem erro vermelho. O Merge fica esperando os dois caminhos chegarem, mas só um chegou. Nada vai pra frente. Sintoma: "meu fluxo continua mas o nó depois do Merge não recebe nada." → Trocar pra Choose Branch. No teste de 16/09, trocar pra Append.

Usar Choose Branch em fluxo paralelo

Resultado: o Merge passa só o primeiro item que chegar e descarta o outro. Sintoma: "perdi os campos da segunda fonte." → Trocar pra Combine by Position.

Combine by Position com quantidades diferentes

Se um caminho tem 3 itens e o outro tem 2, o Merge descarta o terceiro item silenciosamente. Use Combine by Key.

Esperar o Merge "decidir" sozinho

O Merge não infere o modo. Você define no campo Mode.
