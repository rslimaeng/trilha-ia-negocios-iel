Conceito central

O conceito desta aula

API = garçom

Você (o n8n) está sentado na mesa com fome. A cozinha (o servidor da outra empresa: Google, OpenAI, OpenWeather) tem o que você quer, mas você não pode entrar lá. O garçom (a API) leva seu pedido pra cozinha e traz a resposta de volta.

Analogia: a analogia do restaurante

Pontos importantes da analogia:

  • Você não cozinha. Só pede e recebe. O n8n não precisa "ser" o Google Calendar: ele só pede pro Google Calendar criar o evento.
  • Existe um cardápio. A cozinha não faz qualquer coisa. Faz o que está documentado. Esse "cardápio" é a documentação da API.
  • O garçom precisa entender o pedido. Pedido confuso → cozinha não entende → erro. Por isso APIs têm formato fixo.

Mesa, garçom e cozinha, em slide. As setas de ida e volta são o pedido e o prato do desenho acima.

Vocabulário mínimo

5 palavras pra ler 90% das docs de API:

  • Endpoint: endereço onde você faz o pedido. Uma URL: https://api.openweathermap.org/data/2.5/weather. Cada operação tem seu endpoint próprio (/weather, /forecast, /users/42).
  • Método: o verbo do pedido:
    • GET: buscar dado ("me dá os dados de Fortaleza")
    • POST: criar dado ("crie esse novo lead")
    • PUT/PATCH: atualizar dado ("mude o status pra 'qualificado'")
    • DELETE: apagar ("remova o evento 999")
  • Header: informação embalada do pedido. Quem é você (token de autenticação), qual formato você manda (Content-Type: application/json).
  • Body: os dados do pedido (só em POST/PUT). É um JSON com o conteúdo. Pra GET, geralmente não tem.
  • Status code: resposta resumida em número:
    • 200: sucesso
    • 400: pedido malformado (você errou)
    • 401: credencial errada (token inválido)
    • 404: endpoint não existe
    • 429: você fez pedido demais, espera um pouco
    • 500: problema na cozinha (não é seu)

Três das cinco palavras, no cardápio. As outras duas, método e status code, têm slide próprio: o método na aula 2, o status logo abaixo.

Memorize a regra dos 4xx vs 5xx

Começa com 4 = problema seu (erro do cliente). Começa com 5 = problema deles (erro do servidor). Lê o código antes de mexer no fluxo.

A regra dos 4xx e 5xx, em três cores. O "sem crachá" do 401 é a aula 3 inteira.

Como funciona

Como funciona na prática

A jornada de uma chamada: passo a passo

Imagina que você quer saber a previsão do tempo de Fortaleza. O caminho:

Os 5 passos de uma chamada 
1. n8n monta o pedido:
   - Endpoint: https://api.openweathermap.org/data/2.5/weather
   - Método:   GET
   - Query params: ?q=Fortaleza,br&appid=SUA_KEY&units=metric

2. n8n manda o pedido pela internet.

3. Servidor do OpenWeather:
   - Confere a key (header)
   - Consulta o banco de dados
   - Monta a resposta

4. Resposta volta pro n8n:
   - Status: 200 OK
   - Body: { "name": "Fortaleza", "main": { "temp": 28.5 }, ... }

5. n8n entrega o JSON pro próximo nó usar.

Tudo isso em menos de 1 segundo. E o aluno só precisa preencher 3 campos no nó HTTP Request: endpoint, método e a query. O resto o n8n faz sozinho.

Como ler uma doc de API real

Toda doc decente mostra 3 coisas pra cada endpoint:

  1. Qual é a URL (endpoint).
  2. Quais parâmetros aceita (query, header, body).
  3. Como é a resposta (formato do JSON que volta).

E quase toda doc traz um exemplo curl: uma linha de comando que você pode copiar direto pro n8n (atalho mágico do "Import cURL": ver aula 2).

Ao bater numa doc:

  • Procura "Quickstart" ou "Getting started" primeiro: costuma ter o curl pronto.
  • Procura "Authentication": pra saber se precisa de chave e onde colocá-la.
  • Procura o endpoint específico que faz o que você quer (ex.: "Current Weather" no OpenWeather).
  • Confere se tem rate limit (quantas chamadas por minuto/dia).

05
A cerca

Pegadinhas

Confundir endpoint com URL do site

https://openweathermap.org é o site. https://api.openweathermap.org/data/2.5/weather é o endpoint da API. Endereços diferentes, propósitos diferentes.

Achar que GET e POST são intercambiáveis

Não são. Doc fala GET → você usa GET. Trocar dá 405 Method Not Allowed.

Ignorar status code

Aluno vê erro vermelho no n8n e tenta refazer tudo. Lê o código primeiro: 401 = credencial. 404 = URL errada. 429 = espera. 500 = não é problema seu.

Não checar rate limit

API gratuita costuma limitar (60/min, 1000/dia). Workflow que dispara em loop sem freio leva ban temporário.

Esquecer que a API é uma terceira pessoa

Se a API cai, seu fluxo cai. Tema do Error Trigger (B11).
