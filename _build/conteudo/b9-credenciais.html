01
O que você vai aprender

Por que isso importa

Em uma frase

Credencial é como o n8n prova pra cada serviço externo "sou eu, autorizei". Sem credencial certa, nada de Gmail, Sheets, OpenAI, Slack, OpenWeather pago.

Não é decoreba: são 3-4 padrões só, e depois que você cria uma vez, reusa em todo workflow. O segredo é entender qual padrão cada serviço usa antes de tentar conectar.

02
O conceito, e é um só

Conceito central

O conceito desta aula

Credencial = crachá

Analogia

Pensa em credencial como um crachá com seu nome + assinatura da empresa. Cada vez que o n8n quer entrar num serviço (Gmail, OpenAI), ele mostra o crachá. O serviço confere e libera.

  • O crachá = a credencial
  • Quem mostra o crachá = o n8n
  • Quem confere e libera = o serviço (Gmail, OpenAI)

Vantagens de usar credencial em vez de colar token direto no nó:

  • Reuso. Cria 1 vez, usa em 50 workflows.
  • Segurança. Token fica no cofre do n8n. Workflow exportado não vaza o segredo.
  • Atualização central. Token expirou? Atualiza num lugar só, todos os workflows seguem.

O crachá, em slide. Os dois quadros são as duas linhas que resolvem ~90% da tabela abaixo; a dica do rodapé é a primeira pegadinha da cerca.

Os 4 tipos que cobrem 95% dos casos

TipoComo funcionaExemplos
API KeyToken simples colado num campoOpenAI, Groq, OpenWeather, Telegram
Basic AuthUsuário + senha tradicionais (raro hoje)Sistemas legados, alguns webhooks corporativos

Duas linhas desta tabela se perderam na exportação do Notion: OAuth2 e Header Auth. As duas estão descritas por extenso na seção 03, com o passo a passo de cada uma.

OAuth e API Key resolvem ~90% dos serviços modernos. Header Auth aparece quando a API tem padrão próprio. Basic Auth é resíduo de era antiga.

03
Como funciona

Como funciona na prática

Onde criar credencial

Existem 2 lugares que abrem o painel de credencial: escolha o mais conveniente:

  1. Direto no nó: clique no campo Credential to connect with, depois em + Create new credential. n8n já pré-seleciona o tipo certo pro serviço.
  2. Menu lateral: menu Credentials (ícone de cadeado) → Create credential → procura pelo serviço.

Recomendação: direto no nó, primeira vez. Menos passos, e o n8n já sabe qual tipo é.

Conferido na tela em 16/09/2026: onde o menu está hoje

Na versão atual do n8n, Credentials é uma aba da tela Overview (Workflows · Credentials · Executions · Variables · Data tables), sem ícone de cadeado no menu lateral. O botão Create credential fica no canto superior direito dessa tela. O caminho 1, direto no nó, é o mesmo.

OAuth2 (Google, Slack, etc.)

Os 6 passos do OAuth2 
1. No nó Gmail (ou Sheets/Drive/Calendar), campo "Credential" → Create new.
2. Tipo já preenchido: Gmail OAuth2 API.
3. Clique em "Sign in with Google". Popup abre.
4. Escolhe a conta. Autoriza os escopos (read e-mail, send e-mail, etc.).
5. Volta pro n8n com "Account connected".
6. Salva.
Pegadinha do OAuth Google

O setup do Google Cloud Console (criar projeto, ativar APIs, gerar OAuth Client ID) é denso. Aluno tropea aqui mais que em qualquer outra coisa do B9. Tema com vídeo standalone dedicado: assiste 1 vez, tira do caminho.

Atalho do n8n Cloud

Se você usa n8n Cloud (não self-host), as credenciais OAuth do Google já vêm pré-configuradas. Você só clica em "Sign in" e autoriza. Zero Cloud Console. Mais um motivo pra começar no Cloud.

API Key (OpenAI, OpenWeather, Groq)

Os 5 passos da API Key 
1. No site do serviço (ex.: platform.openai.com), gera a key.
2. Copia o token (sk-... no caso do OpenAI).
3. No nó OpenAI Chat Model → Credential → Create new.
4. Cola o token no campo "API Key".
5. Salva.
Pegadinha universal

Quase todo serviço mostra a API key UMA vez na tela de geração. Se você fechar antes de copiar, gera de novo. Não tem como recuperar a anterior.

Header Auth (APIs customizadas)

Útil quando uma API quer um header específico (ex.: X-API-Key: SEU_TOKEN).

Os 4 passos do Header Auth 
1. Menu Credentials → Create credential → "Header Auth".
2. Name: nome do header (ex.: X-API-Key).
3. Value: o token.
4. Salva. Agora qualquer HTTP Request node pode usar essa credencial.

Reuso entre workflows

Toda credencial criada aparece no menu lateral Credentials e é selecionável em qualquer workflow do mesmo projeto. Não precisa criar de novo. Crie uma só "Gmail principal" e use nos 30 workflows que mandam e-mail.

Exemplo guiado: criar credencial OpenAI em 2 minutos

Exemplo guiado · da key ao nó, em 6 passos

05
A cerca

Pegadinhas

401 Unauthorized = credencial

É o sintoma. Causa: token errado, token expirou, escopo OAuth faltando. Refaz a credencial e re-testa.

API key visível só uma vez

Copia na hora ou gera de novo. Não existe "mostra de novo".

OAuth Google expira

Depois de longa inatividade, o Google revoga. Sintoma: workflow que rodava de manhã para de rodar à tarde com 401. Solução: reconectar.

Compartilhar credencial errada com o time

Em n8n self-host, credencial pode ser "Shared" ou "Personal". Confere antes de marcar como Shared: credencial pessoal (Gmail teu) não deve virar Shared.

Confundir API Key com OAuth

OpenAI é API Key. Gmail é OAuth. Se o serviço pede "Sign in with Google" → OAuth. Se pede "cole seu token" → API Key.

Esquecer de revogar credencial de funcionário que saiu

Ele leva o crachá pra casa. Revoga no painel do serviço (não só no n8n).
