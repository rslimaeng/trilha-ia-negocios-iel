01
O que você vai aprender

Por que isso importa

Em uma frase

Este é o kit básico de operação. Sem ele, todo fluxo que você construiu até aqui vive enquanto ninguém encostar nele.

Todo workflow real eventualmente quebra: credencial expira, API muda de formato, planilha chega vazia, valor inesperado aparece. Não é se vai dar erro, é quando.

A diferença entre um operador iniciante e um intermediário é que o intermediário abre o painel certo, lê o que chegou no nó e identifica a causa em 2 minutos. Não é talento: é ordem de conferência.

02
O conceito, e é um só

A execução guardada

O conceito desta aula

Cada vez que o fluxo rodou, o n8n guardou tudo o que aconteceu nó a nó, e é nesse histórico que o erro se acha

É

Ler o que chegou e o que saiu

O painel guarda o dado que entrou em cada nó e o que ele devolveu. O erro quase sempre está na diferença entre os dois.

É

Uma ordem fixa de conferência

Quatro passos, sempre os mesmos, sempre na mesma sequência. A ordem é o método.

Não é

Mexer na configuração do nó vermelho

O nó vermelho é onde o erro apareceu, quase nunca é onde ele nasceu.

Não é

Rodar de novo para ver se passa

Se o dado que chega está errado, ele vai errar de novo. Tentar outra vez é adiar a leitura, não substituí-la.

É como a câmera do corredor do prédio

Sumiu uma encomenda. Você não começa perguntando ao morador do apartamento onde ela deveria ter chegado: começa vendo a gravação, quadro a quadro, até achar o ponto em que ela ainda estava lá e o seguinte em que já não estava. O erro mora entre esses dois quadros, e não no apartamento.

  • A gravação inteira é a execução, que o n8n guarda toda vez que o fluxo roda
  • Cada quadro é um nó, com o que entrou e o que saiu dele
  • O apartamento é o nó vermelho: onde você percebeu o problema
  • Os dois quadros vizinhos são o nó que falhou e o anterior a ele, que é onde se compara

Onde fica a gravação

No menu lateral, em Executions. A lista traz a data, o status, o modo (manual, trigger ou webhook), o tempo e qual fluxo rodou. Clicando numa linha, o canvas abre pintado, mostrando exatamente o que aconteceu em cada nó.

Cor no canvasO que quer dizer
🟢 VerdeO nó executou com sucesso
🔴 VermelhoO nó falhou, e é aqui que está o erro
⚪ CinzaO nó não executou, porque o fluxo não chegou até ele
🟡 AmareloExecutou, mas com um aviso
No agente, cinza não é erro: é escolha

Nos caminhos das tools de um AI Agent, verde quer dizer que a tool foi chamada e cinza que não foi. Se a tool deveria ter sido chamada e ficou cinza, o problema não é o modelo: é o System Prompt. Ou a tool não foi mencionada nele, ou a descrição dela está vaga. O caminho de volta é a aula 3 do B10.

03
Como funciona

O método de 4 passos, sempre nesta ordem

1Abrir a execução que falhou
→
2Ler o que entrou no nó vermelho
→
3Ler o que saiu do nó anterior
→
4Só agora, ler a mensagem de erro

A mensagem de erro é o passo 4, não o 1. Parece contra a intuição, e é de propósito: ler a mensagem primeiro faz você procurar a solução dela, quando o que produziu o erro foi o dado que chegou dois passos antes.

1
Abra a execução com falha

No painel de Executions, clique na execução marcada com ❌. O canvas abre marcando o nó vermelho, que é onde travou.

2
Leia o que entrou no nó que falhou

Clique no nó vermelho e abra a aba Input, na visão JSON. A pergunta é uma só: "esse dado tem o que o nó precisa?"

  • O campo que ele espera está vazio ou undefined?
  • O tipo está errado, "42" com aspas onde devia ser 42 sem?
  • Chegou uma lista vazia onde deviam vir itens?
Quase sempre o problema está no que entrou, não no nó

Se você só guardar uma frase desta aula, guarde esta.

3
Leia o que saiu do nó anterior

Clique no nó anterior ao vermelho e abra a aba Output. Ele deveria ser igual ao Input do nó vermelho. Se for diferente, alguma transformação no meio está alterando o dado, e o conserto é lá.

4
Agora sim, leia a mensagem de erro

A aba Output do nó vermelho mostra o erro completo. Com os passos 2 e 3 feitos, a mensagem deixa de ser um enigma e vira confirmação.

Se você leu os quatro e continua sem saber o que fazer

Escreva a causa numa frase só, mesmo que errada: "o campo X chegou vazio porque o nó Y não mandou". Frase que você não consegue terminar aponta o passo que você pulou.

Não vale: mudar a configuração do nó vermelho para ver se passa. Se o dado que chega está errado, você vai trocar um erro por outro e perder a pista.

A tabela de consulta

ErroCausa típicaOnde olhar

429 Too Many RequestsLimite de chamadas estouradoAdicionar um Wait node

Os quatro primeiros são códigos de resposta HTTP, os mesmos do B9. Os dois últimos são do próprio n8n, e os dois apontam para o mesmo lugar: o passo 2.

04
A demonstração

Quebrar de propósito, para aprender barato

A hora de errar é agora, num fluxo que não importa, e não daqui a três semanas com o cliente esperando.

Exemplo guiado · provocando o erro

O fluxo: Manual Trigger → HTTP Request → Set.

5
Quebre de propósito

Configure o HTTP Request com uma URL que não existe: https://nao-existe.com.br/api. Execute.

Deu certo quando

O HTTP Request ficou vermelho. Era esse o objetivo.

6
Aplique o método

Painel de Executions → clique na execução com ❌ → clique no nó vermelho. O Output mostra o erro de DNS: getaddrinfo ENOTFOUND.

Deu certo quando

Você conseguiu dizer a causa em uma frase: a URL está errada. Corrija para uma válida e execute de novo. ✅

7
A variação, que é a mais útil

Mude o método para POST e não mande corpo nenhum. Execute.

Deu certo quando

Apareceu 400 Bad Request, e ao ler a resposta da API você encontrou "body must be JSON". A API disse o que faltava. Adicione o corpo e execute de novo.

O que essa variação ensina

No primeiro caso o erro veio do n8n; no segundo, veio da API do outro lado. Ler a resposta da API é o que resolve metade dos erros de integração, e quase ninguém faz porque a mensagem parece técnica demais. Ela costuma ser a mais direta das duas.

05
A cerca

Pegadinhas

Não olhar o que entrou no nó que falhou

Quase todo erro de nó vermelho é problema do dado que chegou, e não do nó em si. Sempre o passo 2 antes de mexer na configuração.

Confundir aviso amarelo com erro vermelho

Aviso não impede o fluxo de continuar; erro sim. Se o fluxo terminou bem e tem amarelo, leia, mas não pare por causa dele.

Rodar de novo sem investigar

"Vou tentar outra vez" raramente resolve. Se o dado que chega está errado, ele vai errar de novo.

Esquecer que credencial expira

Acesso a Gmail, Sheets e Calendar é revogado depois de um tempo sem uso. Erro 401 é quase sempre isso.

Dado pinado velho

Se você fixou um resultado antigo, o teste usa o dado velho em vez do que está chegando agora. Se o erro só acontece com dado pinado, despine e rode de novo.
