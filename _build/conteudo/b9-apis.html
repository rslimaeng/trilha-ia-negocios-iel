O n8n deixa de ser uma "ilha"

Aqui o n8n deixa de ser uma "ilha" e passa a conversar com qualquer ferramenta do mundo. Quem domina HTTP Request + Credenciais + Webhook não fica refém de "tem nó nativo?": vira fornecedor de automação.

Explicar API sem jargão (analogia waiter/chef), dominar HTTP Request (4 verbos + Import cURL), configurar OAuth/API Key/Header Auth, usar os 3 nós Google na mesma credencial, e construir mini-API com Respond to Webhook.

O que você leva

Entregável do B9

Fluxo de previsão do tempo (Open-Meteo + Gmail) ativado, rodando todo dia 7h.

Mapa de Capacidades · B9

Ao final, você consegue:

  • Explicar em uma frase o que é uma API usando a analogia waiter/chef.
  • Diferenciar API (você puxa) de Webhook (vem te avisar) e saber quando usar cada um.
  • Identificar em qualquer doc de API: endpoint, método, headers, body e exemplo curl.
  • Fazer uma chamada GET com query parameters via HTTP Request.
  • Fazer uma chamada POST com body JSON e Content-Type correto.
  • Importar um curl da doc e o n8n configura tudo automaticamente (Import cURL).
  • Ler o status code e diagnosticar: 401=credencial, 404=URL, 429=rate limit, 500=problema deles.
  • Criar uma credencial OAuth Google que serve Gmail/Sheets/Drive simultaneamente.
  • Criar uma credencial API Key (OpenAI/Groq/OpenWeather) e reusar em múltiplos workflows.
  • Criar um Webhook que recebe dado e responde com JSON customizado (mini-API).
  • Construir o fluxo "Previsão do tempo" sozinho: Schedule → HTTP Request (Open-Meteo) → Set → Gmail.
03
Confira

Protocolo de Validação

O fluxo está válido quando:
  1. Nenhum nó vermelho na execução.
  2. E-mail chega na caixa com previsão real do dia formatada.
  3. Caso de borda testado: cidade com vírgula nas coordenadas dá erro previsível, e API fora do ar entra como tema do Error Trigger (B11).
