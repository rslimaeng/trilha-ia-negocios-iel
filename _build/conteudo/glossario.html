02
Esqueleto do n8n

Os quatro conceitos que sustentam todo o resto

Workflow

Conjunto ordenado de nós conectados que executam uma automação completa, de ponta a ponta.

Tem um gatilho que dispara, um ou mais nós que processam, as conexões que ditam a ordem, e um estado: ativo ou inativo.

Em uma frase: workflow é a receita; cada execução é o bolo. Aparece no B6.

Node

Bloco que executa uma ação dentro de um workflow. Pode ser ler, escrever, transformar, decidir ou esperar.

Cada nó tem entradas, saídas, configurações e, se conversa com app externo, credenciais. Os tipos principais: os que disparam, os que executam tarefas, os que controlam o caminho (IF, Switch, Merge) e os que transformam dados (Set, Code).

Aparece no B6.

Trigger

Nó especial que inicia um workflow. Sem gatilho, o fluxo não roda.

Pode ser disparado por clique manual, horário marcado, chegada de uma requisição, envio de formulário, ou evento num app externo.

Todo fluxo tem um e apenas um gatilho no início. Não dá para ter dois no mesmo fluxo, mas dá para ter dois fluxos escutando o mesmo evento. Aparece no B7 e na referência de gatilhos.

Execution

Cada vez que um workflow roda. O n8n guarda o histórico, e você vê o que aconteceu nó a nó.

Toda execução tem status, horário de início e fim, o que a disparou, e o que entrou e saiu de cada nó. Você pode reabrir uma antiga e re-executar a partir de qualquer nó, o que é útil para achar erro.

Aparece no B11, aula 1.

03
Dados e configuração

Os dois conceitos que você configura

Credential

A chave ou login que o n8n usa para conversar com um app externo.

As credenciais ficam separadas dos fluxos: você cria uma vez e reusa em quantos quiser. Os tipos comuns estão na referência de integrações.

  • Nomeie de forma clara, com a conta dentro do nome.
  • Revogue quando trocar de conta, ou quando alguém sair da equipe.
  • Não compartilhe sem necessidade.

Aparece no B9, aula 3.

Expression

Jeito dinâmico de preencher um campo: em vez de texto fixo, uma fórmula que pega dado de outro nó.

Escreve-se entre chaves duplas. As mais usadas estão na referência de dados. O campo tem dois modos: Fixed, que é texto literal e não muda, e Expression, que calcula a cada execução.

Aparece no B8, aula 4.

04
IA

Os cinco conceitos do agente

AI Agent

Nó que combina modelo, memória e ferramentas para decidir e executar, em vez de só responder texto.

Tem três componentes: o modelo, que é o motor de raciocínio; a memória, que guarda o contexto; e as ferramentas, que são as ações que ele pode chamar. Diferente de uma chamada solta, ele lembra do que foi dito, decide qual ferramenta usar, e executa vários passos até completar.

Quando não usar: para resumir, classificar ou traduzir um texto único, um nó especializado é mais barato. Ver a referência de IA.

Aparece no B10.

Tool

Ação que o agente pode chamar para executar uma tarefa concreta: enviar e-mail, criar evento, buscar dado em planilha.

No n8n, qualquer nó vira ferramenta ao ser ligado na porta lateral do agente. Cada uma tem um nome curto, uma descrição que diz quando usar, e parâmetros que a IA preenche na hora.

  • Nome em inglês, descritivo, com sublinhado no lugar do espaço.
  • A descrição diz quando usar, não só o que faz.
  • Limite de 5 a 6 por agente. Acima disso, a precisão cai.

Aparece no B10, aula 4.

Memory

Componente que guarda o contexto da conversa entre mensagens, dentro de uma sessão.

Sem memória, o agente esquece tudo a cada mensagem. Com memória, ele lembra do nome que você disse três mensagens atrás e não pergunta o mesmo dado duas vezes.

TipoO que fazNível
Simple MemoryGuarda as últimas mensagens, por padrão 5Iniciante ✅
Window BufferJanela deslizante mais sofisticadaIntermediário
Banco de dadosPersistência entre sessõesAvançado

A memória é vinculada a um Session ID. Sem ele configurado, todas as conversas viram uma só. Aparece no B10, aula 5.

Session ID

O identificador que separa conversas diferentes na memória do agente. Configurar errado é a causa mais comum de "o agente está misturando dados de pessoas diferentes".

Imagine um agente atendendo pelo Telegram. Uma pessoa manda "quero comprar 10 unidades"; outra manda, trinta segundos depois, "qual o preço?". Com o identificador fixo, o agente responde à segunda usando a conversa da primeira. Com o identificador da conversa, cada uma fica isolada.

Os três jeitos errados

Um valor fixo mistura todo mundo. Um valor de teste esquecido faz o mesmo. E o horário atual cria uma sessão nova a cada execução, então o agente esquece tudo.

Em desenvolvimento dá para usar valor fixo, que é mais fácil de depurar. Em produção, nunca. Troque antes de ativar.

System, User e Assistant

Os três papéis que aparecem dentro de qualquer nó de IA. A confusão acaba com uma analogia: você acabou de contratar alguém.

PapelO que éA analogiaFrequência
System Define quem o agente é e como deve se comportar, antes de qualquer conversa. Tem mais peso que qualquer outra instrução. O manual de integração que você entrega no primeiro dia Sempre
User O pedido que chega na hora, ou os dados a processar. Muda a cada execução. O cliente que chega na recepção e faz um pedido Sempre
Assistant Não é um segundo agente. É uma mensagem que você escreve fingindo ser resposta da IA, para mostrar o formato esperado. Mostrar um exemplo de como a pessoa anterior atendia bem Raramente

Na maioria dos fluxos você usa só System e User. O Assistant entra quando você já ajustou o System Prompt e o agente continua errando o formato.

As três pegadinhas dos papéis

System vazio é agente sem treinamento: capaz, mas imprevisível. Tudo no User torna o System inútil, porque some a separação que dá peso às regras. E Assistant com texto inventado, sem ser exemplo claro, confunde o modelo: ele pode achar que aquela resposta já aconteceu.

Aparece no B10, aula 3.
