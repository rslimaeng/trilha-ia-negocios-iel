O que você vai aprender

Por que isso importa

Em uma frase

Aprender o Manual Trigger primeiro é a melhor forma de testar qualquer outro fluxo sem ficar amarrado a horário, evento ou webhook externo. É a sua "ferramenta de bancada" do dia a dia.

Todo fluxo precisa de um trigger pra começar. O Manual Trigger é o "modo zero": você é quem dispara, clicando em Execute Workflow. Parece bobo (e é, no início), mas tem usos legítimos em produção que muita gente ignora.

O slide que abriu o bloco em sala. O dominó laranja é o gatilho; esta aula é sobre a chave mais simples das cinco, a do clique.

O conceito, e é um só

Conceito central

O conceito desta aula

Manual Trigger = clique manual no botão "Execute Workflow" do n8n

  • Entrada: nada
  • Saída: 1 item vazio ({}) que dá início ao fluxo
  • Quando dispara: só quando você clica
  • Quantos por workflow: geralmente 1 só
Analogia

Manual Trigger é o botão de play do seu workflow.

  • O botão de play = o Manual Trigger
  • Apertar = clicar em Execute Workflow
  • O que toca = o fluxo, uma vez

A analogia, em slide. A frase de baixo é a mesma da seção 01: ferramenta de bancada.

03
Como funciona

Como funciona na prática

01

Adicionar

  1. Abra um workflow novo (ou vazio).
  2. Clique duplo no canvas (ou pressione Tab) → busque "Manual Trigger" → adicione.
  3. Renomeie pra algo concreto: ▶️ Disparo Manual ou ▶️ Rodar pra Testar.
02

Disparar

  • Clique em Execute Workflow (canto superior direito) ou aperte Ctrl + Enter.
  • O fluxo roda 1 vez.
03

Ver o resultado

  • Cada nó executado mostra ✅ verde.
  • Clique no nó pra ver o output.

Quando usar Manual Trigger em produção (não é só pra teste)

A maioria dos cursos trata Manual Trigger como "só pra dev". Mas tem 3 casos legítimos em produção:

  1. Aprovação humana antes de rodar. Você quer revisar dados ou condições antes de processar (ex.: relatório que dispara um envio em massa: você confere primeiro, clica depois).
  2. Job sob demanda. Tarefas que rodam "quando precisar", sem horário fixo (ex.: gerar PDF de fechamento mensal: você roda quando o mês fecha de verdade).
  3. Workflow auxiliar chamado por outro. Um workflow principal pode "executar" outro workflow, e quem rodar manual é só pra debugar/testar o auxiliar.

Os três casos, como foram mostrados em sala. O primeiro é o que mais vale guardar: um clique humano antes de um envio em massa é uma proteção, não uma falta de automação.

A demonstração

Exemplo guiado: Hello World do Manual

Vamos construir o exemplo mais básico possível:

Exemplo guiado · Manual Hello
  1. Crie workflow novo. Renomeie pra Manual Hello.
  2. Adicione Manual Trigger → renomeie pra ▶️ Disparo.
  3. Adicione Edit Fields (Set) depois → renomeie pra 📦 Mensagem.
  4. No Set, configure: Mode Manual Mapping; Add Field: mensagem (String) = Hello, manual world!
  5. Clique em Execute Workflow.
  6. Clique no Set → painel direito → Output. Veja { mensagem: "Hello, manual world!" }.

Redesenho do canvas, a partir da execução de teste (execução 415, 16/09/2026). O output do Set saiu { "mensagem": "Hello, manual world!" }.

05
A cerca

Pegadinhas

Achar que Manual Trigger ativa automaticamente

Não ativa. Você precisa clicar. Se nada acontece quando você "ativa o workflow", é porque Manual Trigger ignora ativação: ele só roda no clique.

Esquecer que ele não tem dados de entrada

O primeiro item que sai é {} (vazio). Se o próximo nó precisa de algum dado pra trabalhar, você tem que criar esse dado (com Set, por exemplo) logo depois do Manual.

Tentar usar mais de um Manual Trigger no mesmo workflow

O n8n permite tecnicamente, mas avisa: em geral 1 manual por workflow.

Confundir "Execute Workflow" (roda tudo) com "Execute Step" (roda só o nó selecionado)

Os dois servem: Execute Step é ótimo pra debugar nó por nó depois de pinar o output dos anteriores.
